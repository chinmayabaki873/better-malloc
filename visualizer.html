I. Single mmap() Initialization (1 MB Heap)

Instead of calling sbrk() or asking the OS for memory on every allocation, our allocator obeys the strict project guideline: mmap() is called only once inside Mem_Init().

  • Total Mapped Region: 1,048,576 bytes (1 MB = 256 OS pages of 4,096 bytes).
  • Initial State: The start of the mapped region is cast to a Block *heap_head with 24 bytes reserved for its metadata header and 1,048,552 bytes available as usable data.
void *mem = mmap(NULL, total_size, PROT_READ | PROT_WRITE,
                 MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

II. Inside Each Memory Block (24-Byte Header)

Every block in the heap begins with an in-band 24-byte metadata header stored immediately before the payload pointer returned to the user:

  • size_t size (8 bytes): Usable payload capacity in bytes.
  • int is_free (4 bytes + 4 bytes alignment = 8 bytes): 1 if free, 0 if allocated.
  • struct Block *next (8 bytes): Pointer to the next contiguous block in virtual memory.
typedef struct Block {
    size_t size;        // 8B
    int is_free;        // 8B (padded)
    struct Block *next; // 8B
} Block;                // Total = 24 bytes

III. 8-Byte Alignment, Splitting & Coalescing

To satisfy Objective 1 (Nuances of Building an Allocator), every allocation and free performs three key operations:

  • 8-Byte Alignment: User requests are rounded up to a multiple of 8 bytes (e.g., 100B → 104B) via (size + 7) & ~7 so CPU word accesses never fault.
  • Block Splitting: When a free block is larger than needed by at least 24B (header) + 8B (min payload) = 32B, split_block() carves out a new free block from the remainder.
  • Immediate Coalescing: When Mem_Free() marks a block free, coalesce_all() merges any adjacent free blocks (curr and curr->next) into a single large block to combat external fragmentation.

IV. The 4 Placement Policies (Objective 2)

Different workloads require different search strategies when scanning the free list:

  • First Fit: Scans from heap_head and picks the first free block with size ≥ req_size. Fast, but can clutter the start of the heap.
  • Best Fit: Scans the entire list to find the smallest free block that fits, minimizing leftover waste and saving large blocks.
  • Worst Fit: Scans the entire list to pick the largest free block so the split remainder stays large enough to satisfy future requests.
  • Next Fit: Uses a roving pointer (next_fit_rover) to resume searching where the last allocation finished, avoiding repeated scans of allocated blocks at the front.

V. Shared Library Compilation & Live Bridge (Objective 3)

The allocator is compiled as Position-Independent Code (-fPIC) into a standard Linux shared object libmymalloc.so. Both our C test suite (./test_main) and this web studio (via Python ctypes.CDLL("./libmymalloc.so")) call the exact same compiled binary in real time. 

gcc -Wall -Wextra -O2 -fPIC -shared -o libmymalloc.so mymalloc.c
gcc -Wall -Wextra -O2 -o test_main test_main.c -L. -lmymalloc -Wl,-rpath,.
